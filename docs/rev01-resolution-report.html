33 Admin Dashboards Please Elaborate further the Masters Section.
Status: not completed (in 16.05 review).
 RESOLVED Phase 1

What changed

The collapsible help panel on /masters expanded from 4 short sections to a full A-to-Z guide. Open the page → top → click the disclosure titled "About the Masters section — full guide (open me before you change anything)".

Topics covered (each explained in-app)

  1. What is the Masters section? — explains that every SCA is built from three master templates (Form of Subcontract Agreement, Conditions of Subcontract Agreement, Appendix to the Subcontract Agreement), and that this page is where admin maintains the parent template, not any specific agreement.
  2. Why this matters — three load-bearing reasons: (a) admin never re-types legal boilerplate, only fills [Insert]-style slots called fields; (b) when legal updates a clause, you change it ONCE in the master and every future agreement uses the new wording — old agreements stay frozen on whichever version they were created from; (c) the wizard, the workflow PDF preview, and the final signed PDF all read from the masters — there is no other source of truth.
  3. The three template types — reference table mapping each template type to the field-ID range it owns: Form = F01–F09 (party names, project, scope, price + signature block), Conditions = C01–C14 (the 14 clause sections: scope details, payment terms, retention, programme, defects, LDs, variations, insurance, etc.), Appendix = A01–A23 (the summary table of every variable, mostly auto-pulled from F/C fields).
  4. Template Versions — how the audit trail works — each master keeps a version history. Exactly one version per type is active at any time; older versions stay queryable forever so any agreement created against them can still regenerate its PDF as it was first issued. Clicking Save As New Version inserts a new row, auto-flips the previous active to archived, and re-points future agreements to the new version — without touching historic agreements.
  5. Field Catalog attributes — every field has: Field ID (permanent code, never changes), Label (admin-facing display text, free to edit), Clause number (cross-ref to the legal clause for the deviation report), Input type (text / textarea / number / date / dropdown / multifield), auto_source_field_id (when set, this field auto-pulls from the named source — e.g. A07 sources F08), show_in_appendix, is_required (blocks Submit for Review until filled), default_value (pre-fills the wizard input).
  6. {{FIELD_ID}} placeholder mechanics — inside the master HTML/docx you write {{F02}}, {{C03}}, etc. wherever the rendered PDF should substitute the agreement-specific value. The engine walks the field catalog and replaces every {{FIELD_ID}} with the entered value, HTML-escaped, with numeric fields auto-formatted as 1,000,000.00. Tokens with no matching field stay in the output so stray {{F99}} typos are visible immediately.
  7. Appendix overrides — auto vs locked rows — explains item 35: most appendix rows auto-derive from their source (A07 from F08, etc.); admin clicks Edit on a row to lock a custom value (then future source changes leave it alone); clicks Reset to Auto to re-link to source.
  8. A simple scenario — adding a new clause — step-by-step worked example: legal asks for a new "Performance Bond Type" dropdown in Conditions. Walks (1) open Conditions current version, (2) paste new paragraph with {{C14}} placeholder, (3) Add Field in catalog with Field ID = C14, input_type = dropdown, options = ["Bank Guarantee", "Company Undated Cheque"], (4) mark show_in_appendix=true if it should also appear in the Appendix, (5) Save As New Version, (6) create a test agreement — Step 3 now shows the new dropdown, value lands at {{C14}} in the PDF, (7) open an older agreement — still shows previous version without the new clause.
  9. Things to be careful about — never change an existing Field ID (use a new ID + deprecate old); removing a field that historic agreements reference renders empty values (prefer deactivation); the first letter of Field ID is load-bearing (F = Form template, C = Conditions, A = Appendix); editing template HTML is non-destructive — use Save As New Version rather than overwriting.
